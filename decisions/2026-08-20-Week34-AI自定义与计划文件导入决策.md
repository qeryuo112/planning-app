# Week 34 决策：AI API 自定义与计划文件导入

> 日期：2026-08-20
> 决策：用户个人使用版 Plan App 支持用户级 AI 配置，并支持上传计划文件由 AI 解析生成分层目标/任务。

---

## 背景

- 用户希望不依赖服务端统一 AI Key，允许每个人使用自己的 API Key。
- 用户希望把已有的文字计划（总计划、周计划）直接导入 App，由 AI 解析成结构化数据，而不是重新口述。
- 服务器性能有限，构建必须在本地完成；后端部署继续使用“本地构建 + 上传 dist”模式。

## 决策内容

### 1. 用户级 AI 配置

- 在 `User` 模型新增四个字段：`aiProvider`、`aiModel`、`aiBaseUrl`、`aiApiKey`。
- 新增 `GET /users/me/ai-config` 与 `PATCH /users/me/ai-config`。
- `ModelAdapter` 每次调用时根据用户配置创建 OpenAI 兼容客户端；未配置或 apiKey 为空时回退到服务端 `.env` 环境变量。
- `aiProvider` 仅用于日志标签，不影响实际请求路由。

### 2. 计划文件导入

- 新增 `POST /ai/plan-drafts/from-file`。
- 支持 `scope=master` 与 `scope=weekly` 两种模式：
  - `master`：生成总目标、子目标、里程碑、习惯。
  - `weekly`：必须提供 `parentGoalId`，基于已有目标生成带 `scheduledDate` 的具体任务。
- 文件内容直接作为文本上传（txt / md / json），不保存原始文件。
- AI 输出统一走 `PlanDraftPayload` schema，复用现有的 `approveDraft` 确认落库。

### 3. 移动端入口

- 新增 `AiConfigScreen` 与 `AiPlanImportScreen`。
- 入口放在 `MoreScreen` 的「AI 设置」与「计划文件导入」。
- 依赖 `file_picker` 读取本地文件内容。

### 4. 部署与构建

- 后端：本地 `npx tsc --build --force tsconfig.json`，上传 `dist/` 到服务器 `/opt/planning-app/services/api/dist/`，重启 systemd 服务。
- 移动端：本地构建 APK 与 Windows EXE，产物入 `releases/` 但不入 Git。

## 影响

- 用户可使用任意 OpenAI 兼容接口（DeepSeek、Kimi、Claude 代理等）。
- 计划文件导入减少重复录入，支持“总-周”两层计划工作流。
- 新增依赖 `file_picker`；Android 需文件读取权限（`withData: true` 已处理）。

## 风险

- 用户自定义 Key 泄露风险：仅保存在服务端数据库，移动端输入框默认隐藏。
- 文件格式自由度大，AI 解析可能不稳定；后续可补充结构化模板或校验。
- 周计划日期解析依赖文件内文字描述，可能不够精确。
