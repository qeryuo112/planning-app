# Plan 实现计划

> 基于《Plan 产品与技术实现方案》（MVP 方案讨论稿，2026-08）整理。

## 1. 项目定位

构建一款以“目标—计划—执行—反馈—调整”为核心闭环的 AI 个人成长管理工具。核心价值是把模糊愿望转化为可执行的每日行动，并通过打卡反馈帮助用户保持节奏。

MVP 成功标准：
- 3 分钟内创建目标并得到首周可执行计划。
- 每日首页快速呈现“今天最重要的 3 件事”。
- 完成任务后即时看到目标进度、连续打卡和阶段反馈。
- 用户可随时调整计划，AI 不覆盖用户已有数据。

## 2. 推荐技术栈

| 层级 | 技术 |
|------|------|
| 客户端 | Flutter（跨平台统一 UI） |
| 服务端 | NestJS + TypeScript |
| 数据库 | PostgreSQL |
| 缓存/队列/限流 | Redis |
| 实时通信 | SSE（AI 流式输出）、WebSocket（多端同步） |
| 对象存储 | 阿里云 OSS / MinIO（MVP 阶段可延后） |
| 可观测性 | Pino 结构化日志 + Prometheus / Grafana（逐步接入） |
| 部署 | Docker + Docker Compose |

## 3. MVP 功能范围

聚焦一个核心闭环：创建目标 → AI 生成 7 天计划 → 用户确认 → 今日执行 → 每日打卡 → 看到进度 → 周末复盘 → AI 调整下一周计划。

### 3.1 客户端模块

- **今日页**：今日重点任务、日程时间线、目标进度、连续打卡、AI 快捷入口。
- **收件箱**：快速记录的想法和任务先进入收件箱，再整理到目标/项目/日程。
- **任务管理**：清单/看板/日历视图、子任务、优先级、标签、重复规则、延期/跳过/补记。
- **目标中心**：长期/中期/短期目标层级、里程碑、关联项目与任务、AI 重新拆解入口。
- **习惯打卡**：独立于目标体系的习惯列表、每日打卡、连续记录、最低完成标准。
- **AI 工作台**：嵌入目标、任务、复盘场景，输出结构化计划草案并支持人工确认。

### 3.2 服务端模块

- 用户与鉴权（JWT）。
- 目标、里程碑、项目、任务、日程、提醒 CRUD。
- 打卡记录与统计。
- AI 计划草案生成、版本管理、确认落库。
- 日/周复盘生成。
- 用户行为事件埋点。

## 4. 核心数据模型

实体清单：

- `User`：用户与偏好（时区、可用时间、精力曲线、通知设置）。
- `Goal`：长中短期目标，支持 `parent_id` 自关联层级。
- `Milestone`：目标阶段与权重。
- `Project`：可执行项目。
- `Habit`：独立习惯，可选关联目标。
- `Task`：任务（MVP 合并 Template + Instance，通过 `repeat_rule` 区分）。
- `CalendarEvent`：日程事件，可关联任务。
- `Checkin`：打卡事实，支持关联 Task / Habit。
- `Reminder`：提醒/通知。
- `PlanVersion`：AI / 手动计划版本，记录来源、payload、用户反馈、确认时间、回退版本。
- `AISession` / `AIOperation`：多轮对话上下文与 AI 调用链路审计。
- `Review`：日/周复盘。
- `UserEvent`：用户行为事件，用于漏斗与留存分析。

## 5. AI 实现方式

### 5.1 三层架构

1. **模型适配层**：统一对接不同模型供应商，屏蔽鉴权、限流、重试、流式输出。
2. **计划编排层**：提示词模板、上下文组装、JSON Schema 校验、版本 diff。
3. **业务执行层**：把通过校验的计划写入目标、里程碑、任务、日程和提醒。

### 5.2 结构化输出协议

AI 生成计划必须输出符合 JSON Schema 的结构化对象，包含：

```json
{
  "goal": { "title", "horizon", "start_date", "due_date", "success_criteria" },
  "milestones": [{ "title", "due_date", "weight" }],
  "tasks": [{ "title", "date", "duration_minutes", "energy_level", "repeat_rule", "milestone_ref", "minimum_standard" }],
  "habits": [{ "title", "frequency", "preferred_time", "energy_level" }],
  "assumptions", "warnings",
  "estimated_weekly_load": { "total_minutes", "high_energy_minutes" }
}
```

字段说明：
- `energy_level`：高/中/低，用于匹配用户精力曲线。
- `minimum_standard`：最低完成标准，降低挫败感并支撑连续打卡。
- `estimated_weekly_load`：与用户可用时间交叉校验，防止过载。

### 5.3 计划版本与人工确认

AI 输出先保存为 `PlanVersion` 草案，不直接覆盖正式计划。关键字段：
- `source`：用户创建 / AI 生成 / AI 调整 / 手动编辑 / template。
- `approved_by_user`：是否经过确认。
- `rollback_version`：可回退到上一版本。
- `diff`：本次变更了哪些目标、任务、时间和权重。

### 5.4 MVP 策略：预置模板 + AI 微调

MVP 阶段不引入完整 RAG。预置 5—10 个高质量领域模板（如考研英语、减脂入门、晨间习惯），解决冷启动和输出稳定性问题，同时降低 token 成本。

### 5.5 反馈闭环

- 即时反馈：用户对草案提供结构化反馈（“太难了”“时间不合适”）。
- 执行反馈：延期/跳过时记录原因标签（“时间不够”“难度超预期”“动力不足”）。
- 用户画像摘要：长期积累后形成轻量级画像，AI 生成新计划时自动修正偏差。
- A/B 提示词测试：通过 `prompt_version` 区分，对比计划采纳率和首周完成率。

## 6. 进度与打卡算法

### 6.1 任务完成率

```
任务完成率 = 已完成任务权重之和 / 计划任务权重总和
```

延期任务不直接永久影响总分，区分“当前执行率”和“历史完成率”。

### 6.2 目标进度

```
目标进度 = Σ（里程碑完成度 × 里程碑权重）
```

避免仅按任务数量计算导致进度失真。

### 6.3 连续打卡

基于“当天达到最低完成标准”计算，而非要求所有任务 100% 完成。支持：完成、部分完成、跳过、补打卡四种状态。

### 6.4 执行偏差量化

打卡记录除布尔状态外，还记录：
- 时间偏差：`planned_duration` vs `actual_duration`。
- 排程偏差：`scheduled_date` vs `actual_completed_date`。
- 质量自评：1—5 星。
- 能量匹配度：实际执行时段与 `energy_level` 的匹配情况。
- 阻塞原因标签：用于后续 AI 复盘和调优。

## 7. 开发阶段

### 阶段 0：原型验证

- 今日页、目标页、任务页、计划草案页。
- 用假数据验证 7 日执行闭环。
- 接入第一个模型供应商，跑通结构化 JSON 计划生成与人工确认。
- 预置 5 个领域模板，验证模板匹配 + AI 微调流程。

### 阶段 1：MVP

- 用户登录与基础设置（含精力曲线配置）。
- 长/中/短期目标、项目、任务、子任务、截止日期。
- 独立习惯模块与习惯打卡。
- 今日视图、简单日历、周期任务。
- 每日打卡、连续记录、目标进度。
- AI 生成计划草案并人工确认（基于领域模板）。
- 基础提醒和周复盘。
- 执行偏差记录。

### 阶段 2：增强执行

- 离线模式与多端同步。
- 更强的重复规则、时间块、番茄钟。
- 计划负载检测、延期分析、统计报表。

### 阶段 3：智能化与生态

- 基于长期行为的个性化计划。
- 多模型路由与成本控制。
- 外部日历/邮件/运动设备集成。
- 共享目标、小组挑战、企业能力。

## 8. API 设计要点

- 全局前缀 `/api/v1`。
- 所有写接口支持幂等键。
- AI 接口返回 `request_id`，长任务通过 SSE / WebSocket / 轮询获取状态。
- 计划变更记录审计日志。
- 业务接口不直接暴露模型供应商原始格式。

关键端点示例：

| 功能 | 方法 | 端点 |
|------|------|------|
| 健康检查 | GET | `/api/v1/health` |
| 注册/登录/刷新 | POST | `/api/v1/auth/register` / `login` / `refresh` |
| 创建目标 | POST | `/api/v1/goals` |
| 任务列表 | GET | `/api/v1/tasks?date=YYYY-MM-DD` |
| 完成任务 | POST | `/api/v1/tasks/:id/complete` |
| 打卡 | POST | `/api/v1/checkins` |
| 生成计划草案 | POST | `/api/v1/ai/plan-drafts` |
| 确认计划 | POST | `/api/v1/ai/plan-drafts/:id/approve` |
| 周复盘 | POST | `/api/v1/ai/review` |
