## 1. 项目概述

**Plan** 是一款以「目标—计划—执行—反馈—调整」为核心闭环的 AI 个人成长管理工具。当前版本明确为**个人使用版**，支持用户通过自然语言描述目标，由 AI 在数秒内生成可执行的分阶段计划，并围绕目标、任务、习惯、提醒、复盘、日历、报表等模块提供完整的执行与反馈体验。

### 1.1 MVP 成功标准（已达成）

- ✅ 3 分钟内创建目标并得到首周可执行计划。
- ✅ 每日首页快速呈现「今天最重要的 3 件事」。
- ✅ 完成任务后即时看到目标进度、连续打卡和阶段反馈。
- ✅ 用户可随时调整计划，AI 不覆盖用户已有数据。
- ✅ Android 真机可安装运行，核心流程无崩溃、无白屏。

### 1.2 当前版本信息

- 应用对外名称：**Plan**
- 内部包名：`com.example.planning_app_mobile`
- 后端版本：`0.0.1`
- 客户端版本：`0.0.1+1`
- Flutter SDK：`3.44.9`（stable）
- 后端框架：NestJS 10 + TypeScript

## 8. 关键踩坑记录

1. **GitHub 在 shell 中无法访问**：用户电脑使用 VPN，但命令行 `git clone https://github.com/flutter/flutter.git` 连接超时。最终改用 **腾讯镜像预编译 zip** 下载 Flutter 3.44.9。
2. **服务器 `nest build` 压死 SSH**：单核 ECS 编译 TypeScript 时 CPU 满载，SSH 交换超时。当前改为 **本地构建后上传 `dist/`**。
3. **`tar` 解压路径嵌套**：`tar -xzf planning-app-weekX.tar.gz` 默认创建 `/opt/planning-app/planning-app/` 嵌套目录。需用 `--strip-components=1`。
4. **`nest build` 缓存导致生成不完整**：已有 `dist/` 和 `tsconfig.tsbuildinfo` 时只生成部分 `.d.ts`。需删除后重新构建。
5. **`npx prisma migrate deploy` 不会自动加载 `.env`**：需先 `set -a && source /opt/planning-app/.env && set +a` 或显式导出 `DATABASE_URL`。
6. **SSE 通过 Nginx 被缓冲**：必须配置 `proxy_buffering off; proxy_cache off; proxy_read_timeout 300s;`。
7. **Google OAuth 首次授权需 `prompt: 'consent'`**：否则无法拿到 `refresh_token`。
8. **Health Connect 在国内部分 Android 设备需手动安装**：Google Health Connect 应用。
9. **Android `health` 插件要求 minSdk 26 / compileSdk 36**：需 patch Pub Cache 或统一 `subprojects` 脚本。
10. **Windows `flutter_local_notifications` 不支持 Windows 桌面**：`NotificationService` 中对 `Platform.isWindows || Platform.isLinux` 直接返回。
11. **Windows `firebase_messaging` 不支持 Windows 桌面**：`FcmService` 中 `_messaging` 改为 `FirebaseMessaging?`，桌面平台直接返回。
12. **Android 真机白屏**：`FcmService.initialize()` 在 `runApp()` 前阻塞导致首帧无法渲染；改为 `Future.microtask(() => _uploadToken())` 后解决。
13. **Firebase ProGuard 规则缺失**：R8 压缩后 `*KtxRegistrar` 被移除，导致 `ComponentDiscovery` 警告；新增 `proguard-rules.pro` 后解决。
14. **Flutter `health` 包 `uuid` 字段非空**：无需 null-aware 表达式。
15. **systemd EnvironmentFile 对 JSON 字符串转义不友好**：把 `GOOGLE_APPLICATION_CREDENTIALS_JSON` 直接配置为 JSON 字符串时，`\n` 等转义可能被误解析，导致 `Failed to parse private key`。推荐改为配置 JSON 文件绝对路径，由 `FcmService` 读取文件。
